## Хөгжүүлэлтийн аргачлал

Төслийг **Scrum** аргачлалын дагуу хөгжүүлнэ.

Product Backlog-д хэрэглэгчийн хэрэгцээг User Story хэлбэрээр тодорхойлж, тэдгээрийг Priority болон Story Point-оор үнэлсэн.

Одоогийн Product Backlog:

* **15 User Story**
* **70 Story Point**
* **8 үндсэн функц (Epic)**

User Story бүр Acceptance Criteria-тэй бөгөөд хөгжүүлэлт дууссан эсэхийг уг шалгуураар тодорхойлно.

## Лабораторийн ажлын явц

### Lab 2 — Хэрэглэгчийн хэрэгцээг ойлгох ба User Story бичих

* Step 1 — Асуудлыг тодорхойлох
* Step 2 — Хэрэглэгчийн төрлүүд болон хэрэгцээг тодорхойлох
* Step 3 — User Story бичих
* Step 4 — User Story-г INVEST зарчмаар шалгах
* Step 5 — Product Backlog үүсгэх

Product Backlog-д нийт 15 User Story оруулсан бөгөөд нийт үнэлгээ нь 70 Story Point байна.

### Lab 3 — User Story үнэлгээ ба эхний Sprint төлөвлөлт

* Өмнөх 15 User Story-ийн үнэлгээнд тулгуурлан Sprint төлөвлөх
* Багийн хүчин чадлыг тодорхойлох
* Эхний Sprint-д орох User Story-уудыг сонгох
* GitHub Projects дээр Sprint Backlog удирдах төлөвлөгөө гаргах
* Sprint Goal болон амжилтыг шалгах нөхцөлүүдийг тодорхойлох

3 гишүүн өдөрт тус бүр 1 цаг, 10 ажлын өдөр ажиллах бөгөөд ашигтай цагийн коэффициент 0.6 тул хүчин чадал **18 хүн-цаг** байна. Лабораторийн анхны төлөвлөлтийн хязгаарыг **18 SP** гэж авч, Sprint 1-д **US-01, US-02, US-04, US-07 — нийт 17 SP** сонгосон.

**Sprint Goal:** Баталгаажсан хэрэглэгч бүртгүүлж, нэвтрэн, гээгдсэн болон олдсон эд зүйлээ бүртгэж, олдсон зүйлийг авах аргыг харах боломжтой үндсэн урсгалыг ажилладаг болгох.

### Lab 4 — Kanban урсгал ба хугацааны шинжилгээ

* Sprint 1-ийн **US-01, US-02, US-04, US-07 — нийт 17 SP** бүхий дөрвөн User Story-г найман дэд карт болгон задалсан.
* Trello дээр **To Do → In Progress → Review → Done** урсгалтай самбар байгуулж, In Progress болон Review багана тус бүрд **WIP = 2** хязгаар тогтоосон.
* Картуудын шилжилтээр Cycle Time, Lead Time болон Cumulative Flow Diagram (CFD) гаргаж, Review шатны саатал, сайжруулах боломжийг шинжилсэн.

Сургалтын зориулалттай симуляцийн өгөгдлөөр дундаж **Cycle Time 2.875 өдөр**, **Lead Time 6 өдөр** гарсан. Найман дэд карт нь эх User Story-уудын задаргаа тул Story Point-ийг давхар тооцоогүй.

### Lab 5 — Use Case болон Class Diagram

* Өмнөх шаардлага, User Story-д тулгуурлан draw.io ашиглаж Use Case Diagram болон Class Diagram боловсруулсан.
* Use Case Diagram-д хэрэглэгч, эзэмшигч, олсон хүн, админы үндсэн үйлдэл болон холбоог дүрсэлсэн.
* Class Diagram-д **User, Post, Chat, Message, Handover** гэсэн таван үндсэн классын шинж чанар, үйлдэл, харилцааг тодорхойлсон.

Диаграммуудаар системийн үндсэн хэрэглээ, өгөгдлийн бүтэц болон объектуудын холбоог загварчилсан.

### Lab 6 — Git Branching, Merge Conflict ба Code Review

* Тусдаа feature branch-ууд дээр өөрчлөлт хийж, Pull Request-ээр нэгтгэх урсгалыг туршсан.
* Code review-ийн саналд тулгуурлан кодоо сайжруулж, гурван feature Pull Request-ийг нэгтгэсэн.
* Нэг файлд давхардсан өөрчлөлтөөс үүссэн merge conflict-ийг шийдвэрлэж, нэгтгэсэн кодыг шалгасан.
* Revert Pull Request ашиглан өөрчлөлтийг буцаах үйлдлийг туршсан.

Эдгээр дасгалаар branch, commit, review, merge болон revert ашиглан багийн өөрчлөлтийг удирдах дадлага хийсэн.

### Lab 7 — GitHub Actions CI Pipeline

* Node.js 24 ашиглан олдсон зар үүсгэх, хайх, эзэмшигч тэмдэглэх, хоёр тал баталгаажуулсны дараа зар хаах жижиг CampusFind модуль хэрэгжүүлсэн.
* **15 автомат тест** бичиж, `npm run check` болон `npm test` командаар шалгасан.
* `.github/workflows/ci.yml` файлд **push**, **pull_request** trigger-тэй, Checkout → Setup Node.js → Install → Test гэсэн дөрвөн алхамтай CI pipeline байгуулсан.
* Нэг тестийн `CLOSED` хүлээлтийг зориуд `ACTIVE` болгон өөрчилж CI алдааг илрүүлж байгааг шалгаад, зөв хүлээлтийг сэргээсэн.

Зөв хувилбарт **15 тест амжилттай, 0 алдаатай**; зориудын алдаатай хувилбарт **14 тест амжилттай, 1 алдаатай** гарсан. Засварын дараа бүх тест дахин амжилттай болсон. Модуль нь санах ойд ажилладаг бөгөөд веб интерфейс, нэвтрэлт, өгөгдлийн сан хэрэгжүүлээгүй.

Дэлгэрэнгүй тайлбар, CI run-ийн холбоос болон нотлох зургууд: [Лаб 7-ын README](labs/lab07/README.md).
