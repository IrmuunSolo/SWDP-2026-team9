# Баг 9 — Лаборатори 13-ын хамтарсан гүйцэтгэлийн заавар

**Сэдэв:** AI хэрэгсэл ашиглан код бичих, review хийх
**Хугацаа:** 2 цаг · 13-р долоо хоног (Лекц 13) · CLO5
**Төсөл:** CampusFind / SWDP-2026-team9
**Дараалал:** Г.Нармандах → Л.Ирмүүн → Э.Амарболд
**Гарын авлагын дугаар:** Лаборатори 12 («AI хэрэгсэл ашиглан код бичих, Review хийх»). Багийн дугаарлалт долоо хоногоор явдаг тул **Лаб 13** гэж нэрлэнэ.

Гишүүн бүр CampusFind-д хамаарах нэг жижиг функцийг AI хэрэгслээр бичүүлж, тодорхойгүй ба тодорхой prompt-ийн хариуг харьцуулна. Дараа нь AI-ийн кодыг шүүмжлэлтэй review хийж, тестээр баталгаажуулаад эцсийн засварласан хувилбараа тайланд нэгтгэнэ. Энэ нь **гүйцэтгэх төлөвлөгөө**. Тайлангийн хэсгийг гишүүн бүр бодит ажлынхаа дараа бөглөнө.

## 1. Хүлээлгэж өгөх зүйл (багшийн шаардлага)

1. Ерөнхий ба тодорхой prompt-ийн харьцуулалт: AI-ийн хариу хэрхэн ялгаатай байсан.
2. Эцсийн AI кодын review: олдсон 2–3 асуудал, эсвэл «асуудал олдоогүй, учир нь …» гэсэн үндэслэл.
3. Тестээр баталгаажуулсан эцсийн, засварласан код.

Гишүүн бүр эдгээрийг өөрийн функц дээр гүйцэтгэнэ. Багийн тайлан гурвыг нэгтгэнэ.

## 3. Нийтлэг дүрэм

### 3.1. AI хэрэгсэл ба ил тод байдал

- **Шинэ, контекстгүй session** ашиглана: Claude (claude.ai эсвэл Claude Code), GitHub Copilot Chat г.м. Repo-г нээлттэй үлдээсэн Copilot эсвэл өмнөх ярианы түүхтэй session-д prompt өгвөл «муу prompt»-ийн хариу бодит бус болно.
- Prompt болон AI-ийн хариуг **өөрчлөлтгүй, бүтнээр нь** хадгална. Үсгийн алдааг ч засахгүй.
- Хэрэгслийн нэр, загвар (боломжтой бол), огноо, цагийг бичнэ.
- AI-ийн кодыг шууд хуулж commit хийхгүй. Эхлээд уншиж, ойлгож, review хийнэ.
- AI-ийн анхны кодыг `.js` файлаар хадгалахгүй, зөвхөн `ai-log.md` доторх code block-оор хадгална. Root ESLint нь `labs/`-ийн JS-ийг шалгадаг тул засаагүй AI код lint-ийг унагана.

### 3.4. Review хийх шалгуур (Лекц 13)

| Чиглэл | Асуух зүйл |
| --- | --- |
| Логик | Шаардлага бүрийг хангасан уу? Хилийн утга (яг 5 дахь оролдлого, яг хугацаа дуусах агшин, хоосон утга) зөв үү? Off-by-one бий юу? |
| Аюулгүй байдал | Оролтыг шалгасан уу? Нууц мэдээлэл задарч байна уу? Timing, brute-force, injection-ий эрсдэл бий юу? |
| Найдвартай байдал | Оролтын объектыг mutate хийж байна уу? Дотроо `Date.now()` / `Math.random()` дуудаж тестлэгдэхгүй болсон уу? |
| Стиль | Нэршил, magic number, JSDoc, ESM, ESLint-тэй нийцсэн үү? |
| Тест | AI тест бичсэн бол хилийн тохиолдлыг хамарсан уу, эсвэл зөвхөн амжилттай тохиолдлыг шалгасан уу? |

Асуудал олдоогүй бол «асуудал олдоогүй» гэж бичиж болох ч, юуг шалгаж, яагаад зөв гэж дүгнэснээ үндэслэнэ.

### 3.5. Тест (Лаб 11-ийн AAA зарчим)

Гишүүн бүр `node:test` болон `node:assert/strict` ашиглаж **5-аас доошгүй** тест бичнэ:

- Хэвийн тохиолдол 2.
- Хилийн (edge) тохиолдол 2.
- Mock ашигласан 1. Жишээ: `t.mock.fn()`-ээр гадаад хамаарал (цаг, нууц үг шалгагч, hash функц)-ыг орлуулж, дуудагдсан эсэх, хэдэн удаа дуудагдсаныг шалгах.

Тест бүрийг Arrange → Act → Assert гэсэн гурван хэсэгтэй бичнэ.

### 4.2. Гүйцэтгэх дараалал (гишүүн бүр)

1. `ai-log.md`-ийн толгойг бөглөнө.
2. Шинэ AI session-д **тодорхойгүй prompt** өгч хариуг хадгална.
3. **Шинэ session**-д **тодорхой prompt** өгч хариуг хадгална. Хоёр prompt нэг session-д байвал хоёр дахь хариу эхнийхээс нөлөөлнө.
4. Хоёр хариуг харьцуулж хүснэгт бөглөнө.
5. Тодорхой prompt-ийн кодыг review хийж, олдсон асуудлыг тэмдэглэнэ.
6. Кодыг засаж `<функц>.js`-д хадгална. Тест бичнэ.
7. Шалгах:
   ```
   npm --prefix labs/lab13 test
   npx --no-install eslint labs/lab13 --max-warnings=0
   git diff --check
   ```
8. AI-ийн анхны кодыг (эсвэл тест)-ийг засваргүйгээр туршсан бол унасан тестийн гаралтыг `ai-log.md`-д хадгална. Энэ нь review-ийн хамгийн хүчтэй нотолгоо.
9. Тайлангийн өөрийн хэсгийг бөглөж commit, push, PR нээнэ.
