## 1. Зорилго ба deliverable

1. Улирлын турш хөгжүүлсэн CampusFind-ийг 5–7 минутад бүрэн, тодорхой танилцуулах.
2. CI/CD, тест, AI ашиглалтыг амьд демогоор харуулах.
3. Бусад багийн ажлыг peer evaluation маягтаар үнэлэх.

**Багшид өгөх:** танилцуулгын слайд/тэмдэглэл + демо төлөвлөгөө.

## 4. Амьд демогийн дараалал

### 4.1. Демогийн өмнө (30 минутын өмнө)

```
git switch main
git pull --ff-only origin main
npm ci
npm run check
npm test
docker compose -f devops/compose.lab09.yaml -f devops/compose.lab14.yaml up -d --build
```

- Web `http://localhost:15173`, Grafana `http://localhost:3001` нээгдэж байгааг шалгана.
- Демогийн хэрэглэгч (баталгаажсан и-мэйлтэй) ба 2–3 жишээ зарлалыг урьдчилан үүсгэнэ. Бодит хувийн мэдээлэл ашиглахгүй.
- Browser-ийн tab-уудыг дарааллаар нээнэ: апп, GitHub Actions, Grafana.
- Дэлгэцийн мэдэгдлийг унтрааж, фонтыг томсгоно.

### 4.2. CI/CD демо

1. Урьдчилан бэлдсэн `demo/lab16-ci` branch дээр жижиг, аюулгүй өөрчлөлт (жишээ нь нүүр хуудасны текст эсвэл нэг тест нэмэх) хийнэ.
2. Танилцуулга дээр: `git commit` → `git push` → PR нээх → Actions tab-д run эхэлснийг харуулах.
3. CI 2–4 минут үргэлжилдэг тул хүлээхгүй. Дараагийн хэсгийг (AI, сурсан зүйл) ярьж байх хооронд дуусна. Төгсгөлд ногоон болсныг харуулна.
4. Нөөц: урьдчилан амжилттай дууссан run-ийн screenshot болон 1 минутын дэлгэцийн бичлэг (`labs/lab16/ci-demo.mp4`, repo-д биш, локал хадгална).

### 4.3. Аппын демо нөөц

Сүлжээ эсвэл Docker асуудалтай бол урьдчилан бичсэн 90 секундын видео, screenshot-оор үргэлжлүүлнэ. Демо унавал «нөөц бичлэгээр үргэлжлүүлье» гэж шууд шилжинэ.

## 5. Асуулт хариултын бэлтгэл

Гарын авлагад 3 асуулт шаардсан. Нэмэлт 3-ыг нөөцөд бэлдэнэ. Хариулт бүр 30–45 секунд.

| № | Асуулт | Хэн | Хариултын гол санаа |
| --- | --- | --- | --- |
| 1 | Яагаад энэ архитектурыг сонгосон бэ? | Амарболд | NestJS-ийн module/controller/service давхарга нь үүргийг салгаж тестлэхэд хялбар; contracts-ийн нэг validation; PostgreSQL-ийн ACID, constraint, full-text хайлт; Docker-оор орчныг ижилсүүлсэн |
| 2 | AI-г хэрхэн ашигласан бэ? | Нармандах | Тусламж болгон ашигласан, prompt-ийг тодорхой болгосон; AI-ийн кодыг review, тестээр шалгасан; prompt, хариуг өөрчлөлтгүй log-д хадгалсан; AI алдаатай код бичсэн жишээ |
| 3 | Аюулгүй байдал, чанарыг яаж хангасан бэ? | Ирмүүн | 5 оролдлогын түгжээ, их сургуулийн и-мэйл баталгаажуулалт, CSRF хамгаалалт, нууц үгийн hash; ESLint, npm audit, unit/integration тест CI-д; PR review дүрэм |
| 4 | DORA үзүүлэлт тань ямар байсан бэ? | Амарболд | Лаб 15-ын repo тооцоолол, proxy-ийн хязгаарлалт |
| 5 | Хамгийн хэцүү байсан зүйл юу вэ? | Нармандах | Ретроспективын бодит дүгнэлтээс |
| 6 | Цаашид юуг хөгжүүлэх вэ? | Ирмүүн | Product backlog-ийн дараагийн priority |

Мэдэхгүй асуултад таамаглахгүй: «Үүнийг шалгаж үзээгүй, гэхдээ …» гэж шударга хариулна.
