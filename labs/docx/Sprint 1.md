## Одоо хийх зүйл

GitHub Project-ийг шалгахад 15 story бүгд Todo, Assignees хоосон, Story Points нийт 70 байв. Browser-д GitHub нэвтрэлт байхгүй тул Project-д өөрчлөлт хийгээгүй. Тайлан дахь хариуцагчид болон Sprint сонголт нь бэлтгэсэн төлөвлөгөө; хэрэгжүүлж дууссан гэж үзэхгүй.

1. [Project](https://github.com/users/IrmuunSolo/projects/2/views/1)-д өөрийн бүртгэлээр нэвтэрнэ.
2. Тайлангийн «GitHub Projects дээр бүрдүүлэх» таван үйлдлийг хийнэ. Issue #1, #2, #4, #7-г сонгоно.
3. Assignees: #1 — Л.Ирмүүн; #4 — Г.Нармандах; #2, #7 — Э.Амарболд. Гишүүдийн GitHub username-ийг нэртэй нь тулгаж сонгоно. Сонголтод байхгүй бол Notes-д хариуцагчийн нэрийг түр бичээд repository-ийн хамтын ажиллагааны эрхийг багийн эзнээр шалгуулна.
4. `Sprint 1 Backlog` view-д дөрвөн мөр, нийлбэр 17, Sprint талбарын `Sprint 1` утга байгаа эсэхийг шалгана. `Status` шүүлтүүрээр байнгын Sprint view үүсгэхгүй.
5. Доорх текстийг Project details → README хэсэгт одоогийн тайлбарыг хадгалан нэмж оруулна.
6. Тайлангийн Зураг 1–3-ын зааврын дагуу screenshot авч, Markdown эхэд зураг оруулан PDF-ийг шинэчилнэ. Одоогийн PDF-д бодит screenshot ороогүй, харин зураг авах тодорхой заавар бий.

## Project README-д нэмэх текст

```markdown
## Sprint 1

Хугацаа: 2 долоо хоног буюу 10 ажлын өдөр.
Баг: 3 хүн, өдөрт хүн бүр 1 цаг, ашигтай цагийн коэффициент 0.6.
Ашигтай хүчин чадал: 1 × 3 × 10 × 0.6 = 18 хүн-цаг.
Лабораторийн анхны төлөвлөлтийн хязгаар: 18 SP; сонгосон ачаалал: 17 SP.
Энэ нь анхны таамаг бөгөөд бодит velocity-г Sprint Review дээр тогтооно.

### Sprint Goal
CampusFind-ийн баталгаажсан хэрэглэгч бүртгүүлж, нэвтрэн, гээгдсэн болон олдсон эд зүйлээ бүртгэж, олдсон зүйлийг авах аргыг харах боломжтой үндсэн урсгалыг ажилладаг болгох.

### Sprint Backlog
- US-01 / #1 Сургуулийн бүртгэл — 5 SP 
- US-02 / #2 Нэвтрэх, гарах — 2 SP 
- US-04 / #4 Гээгдсэн эд зүйл бүртгэх — 5 SP 
- US-07 / #7 Олдсон эд зүйл бүртгэх — 5 SP 

### Амжилтын шалгуур
- Сургуулийн домэйн, оюутны кодын шалгалт болон и-мэйл баталгаажуулалт ажиллана.
- Нэвтрэх, гарах, 5 буруу оролдлогын дараах 10 минутын түр хаалт ажиллана.
- Гээгдсэн эд зүйлийн заавал бөглөх талбар, байршил, хадгалалт ба жагсаалт ажиллана.
- Олдсон зүйлд шилжүүлэх арга, шаардлагатай үед байр сонгож бүртгэнэ.
- Дөрвөн story-ийн Acceptance Criteria хангагдаж, код хянагдан, нэгдсэн урсгалын тест амжилттай байна.
```

## Баталгаажуулсан өгөгдөл

Story Point ба Priority-г амьд GitHub Project болон repository-ийн issue-уудтай тулгасан. Өмнөх тайланд US-03-ыг Medium гэж тайлбарласан боловч одоогийн Project ба issue-д High байна; тайлангийн сонголтыг одоогийн өгөгдөлд тулгуурлав. Хуучин `.xls`-ийг өөрчлөөгүй, шинэ Excel үүсгээгүй. `.xls`-ийн агуулгыг унших сан энэ орчинд байхгүй тул хүснэгтийн утгыг GitHub болон өмнөх PDF-ээр баталгаажуулсан.

Sprint-ийн эхлэх/дуусах календарийн огноо өгөөгүй тул зохиомол огноо оруулаагүй. Эхлэх огноогоо тогтоосны дараа Project README-д бичнэ.
